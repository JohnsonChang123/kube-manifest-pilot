01 · 首選入門範本

前後端各單副本

為獨立的前端與後端容器建立 Deployment 和 Service，適合一般 Web application 的開發或示範環境。

預計產生

  • Namespace、Frontend Deployment／Service
  • Backend Deployment／Service
  • 依選擇加入 Ingress 或 LoadBalancer

「單副本」代表 replica 為 1，不代表指定到單一 Kubernetes Node。

使用這類問卷開始 →

02 · Stateful Workload

PostgreSQL 單副本

以 StatefulSet、Service 與持久化儲存建立最小 PostgreSQL manifest，適合學習、測試與非高可用環境。

預計產生

  • Namespace、StatefulSet、Service
  • volumeClaimTemplates 與儲存設定
  • 既有 Secret 的名稱與 Key 參照

此範本不是 HA，不包含自動備份、故障切換或資料庫 Operator。

使用這類問卷開始 →

03 · Static or SPA

純前端

為 Nginx、靜態網站或 Single-page application 建立 Deployment 與 Service，並選擇 port-forward、Ingress 或 LoadBalancer。

適合情境

  • 靜態網站與前端 build image
  • 不需要同時建立 API 或資料庫
  • 需要獨立調整 probe 與資源限制
使用這類問卷開始 →

04 · API Service

純後端

為 API、worker-facing service 或 microservice 建立 Deployment、Service、probe、資源限制與設定參照。

適合情境

  • 單一 HTTP API 或內部服務
  • 資料庫與其他服務已在外部管理
  • 需要 ConfigMap 或既有 Secret 參照
使用這類問卷開始 →

05 · Full Stack

前後端＋PostgreSQL

將前端、後端與內建單副本 PostgreSQL 整合成一組輸出，並按照相依順序產生部署與驗證教學。

預計產生

  • 兩組應用 Deployment／Service
  • PostgreSQL StatefulSet、Service 與持久化儲存
  • 選配 Ingress、PDB 或 HPA

內建資料庫仍是單副本；Production 使用前必須另行規劃備份、還原與可用性。

使用這類問卷開始 →

06 · External Database

後端＋外部 PostgreSQL

只建立後端工作負載，將資料庫視為外部相依服務；不會產生 PostgreSQL Pod 或 PersistentVolumeClaim。

需要準備

  • 可由 Cluster 存取的資料庫主機與連接埠
  • 既有 Kubernetes Secret 的名稱與 Key
  • 網路、TLS 與資料庫權限設定
使用這類問卷開始 →

Generation Rules

所有範本共用的生成原則

  • Service selector 與 Pod labels 必須一致，targetPort 必須對應 Container Port。
  • Production 不接受 latest 或缺少版本的 image。
  • Production 只引用既有 Secret，不要求或保存密碼內容。
  • 輸出不得留下 CHANGE_ME、REPLACE_ME 或未替換的指令佔位符。
  • 網頁驗證不等於叢集相容性保證；部署前仍應執行 client 與 server dry-run。
